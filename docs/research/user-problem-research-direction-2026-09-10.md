## 审查发现

1. **根因置信度提前升级。** Magentic-One 的组合消融不能把贡献归因于单一 Frontier；LLMCompiler 特定并行任务结果不能外推为本项目效率收益。见[一手证据核验](frontier-evidence-audit-2026-09-10.md)。Mission Frontier 值得保留为候选机制，尚不能作为主因确诊。
2. **把规则覆盖不足与运行不落实混为一谈。** Spec §2第3项已规定额外动作的边际价值与充分即止，Playbook §13 已规定独立评估双会话退化。尚未确定需要新增事件触发机制，也不能仅靠文本证明运行中完全没有状态更新。
3. **以更多自觉要求治疗不自觉执行，存在循环论证。** “每次结果回来内部刷新四问”仍依赖同一个模型记得触发。需要比较它与替换现有冗余指令、现有状态指针、宿主实际反馈机制的差异；不能把提示词当持久状态或后台执行引擎。
4. **用户问题被最新假设遮蔽。** 文件规模、单次工具输出和整个会话压力是不同变量。文件硬门禁无法直接控制 Browser 重复研究；任务前沿也不能保证 IDE 读取完整或避免输出截断。
5. **停止判据可能误伤必要验证。** 调查没有支持原假设也可能排除错误方向；一次检查没有发现 bug 也可能完成必要门禁。应依据预期决策价值和证据缺口判断，而非事后“无新信息”就判浪费。Gate 满足也不覆盖新发现的实质风险。
6. **代理指标替代真实目标。** 更少行数、规则、工具调用或中继次数，都不自动意味着更快正确交付。强制拆分可能增加跨文件读取；并行可能增加汇聚成本；更少交接可能让单次运行更贵。#40 的负成本反馈必须纳入候选选择。
7. **证据选择偏向减法结论。** AGENTS.md 研究存在不同结果：[Gloaguen 等 v2](https://arxiv.org/abs/2602.11988v2)报告平均成本增加且成功率无普遍改善；[Lulla 等 v2](https://arxiv.org/abs/2601.20404v2)在 10 仓库、124 PR 设置下观察到中位耗时和输出 token 降低。这些设置和指标不同，不能简单抵消，也不能支持普遍“加规则有害”。
8. **规则生效的前置条件尚未核实。** 必须区分发布文件、用户实际加载版本、相关规则是否进入上下文、触发是否发生及执行结果。若 Browser 未实际部署 v0.14，应先解决版本事实，不能据此判断 v0.14 机制失效。

## 新研究总问题

在保留必要质量、证据、授权和用户决策边界的条件下，哪些最小干预能减少 Browser ↔ IDE 协作中的无价值工作与人工负担，并让 IDE 在实际上下文限制内可靠完成任务？

Mission Frontier 作为竞争候选，不预设为统一架构。研究应同时允许“不加新机制、只删重复要求或缩小读取”的答案。

## 调研顺序与停止条件

1. **从现有材料提取需求与失败片段。** 复用引用对话和 #32/#40；优先选择 2–4 个已有、可定位的失败片段。记录当时输入、已有证据、下一动作、用户负担及版本已知程度。缺日志标为 Reported，不要求先开发采集程序。已有材料不足只限制归因强度，不阻止比较候选方案。
2. **对照竞争解释。** 至少区分：部署/加载偏差；状态更新缺失；已有停止规则未执行；交接粒度过细；上下文或工具输出问题；必要验证/服务等待。每个解释写出支持它和会推翻它的观察，避免只寻找支持 Frontier 的论文。
3. **定向读取成熟机制。** 两项编排论文已完成数字与迁移边界核验；上下文研究优先参考 [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) 的定向检索与工具输出控制。后续只补足会改变候选选择的来源。训练算法、离线轨迹剪枝、可控制 runtime、普通提示词分别标注，不能将训练收益直接许诺给提示规则。
4. **提出最小可比较候选。** C0：经核实的现行有效部署基线；C1：仅精简/重排现有规则并澄清 Gate；C2：针对残余状态问题的最小更新机制，区分Prompt和State实现。先从现有证据评估C0覆盖与C1类处理，只有残余状态失真证据会改变方案选择时才推进C2；不要求先运行C1实验，已有trace也可支持判断。当前实际部署未知，候选比较尚非实测结论。上下文治理单独处理，不与所有效率机制捆绑成一次大改。
5. **先做片段推演，再决定是否运行。** 推演只检验设计是否自洽，不能证明实际提速。未来若恢复真实实验，采用同起点、条件可比、必要时重复的少量案例，复用现有评测协议；观察正确交付、必要门禁、可避免中断、总耗时/成本。不可见 token 标 unknown，不能凭回复长度估算实际使用量。测试设计服务于决策，不成为全项目基础设施前置。
6. **足够选择即停止。** 每条主线已能说明优先候选、适用条件、反例、最小修改位置及未验证项，即结束本轮方向研究。若候选没有可观察行为差异或增加用户成本，删去/重写，不继续堆术语。正式规则修订和发布仍走既有门禁。

## 必须保留的反例

- Gate 已完成且无新风险：应交付；出现新的承重风险：不能用“充分即止”忽略。
- 共享可变资源或真实依赖：保留必要串行；独立读取：比较批量/并行净收益。
- 一次无发现的必要测试：可能有价值；无变化地重新读同一证据：需要具体理由。
- 900 行但职责单一、可定向访问：不机械拆分；很多小文件造成反复跨文件追踪：检查拆分副作用。
- Browser 上下文较长、IDE 状态健康：独立判断，不能联动重启。
- 回放中表现好但真实执行成本增加：不能判定效率修复。

### 1. 新证据带来的修正

- [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)支持分别管理指令、工具输出及累积历史；文中也明确 minimal 不等于 short。不能把缩短 Instructions 本身设为优化目标。
- [Anthropic long-running harness](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)使用功能状态、进度文件和 Git history 连接多个 context windows，也要求增量实现和验证。它是 web app harness 的组合方案；不能据此认定单独 compaction 总是无用，或每个 Browser 会话都需要新的进度文件。
- [Ledger v1](https://arxiv.org/html/2608.00808v1)的收益数字与用户引用吻合，但 Codex 组使用 MiniMax M2.5；不是用户当前 Codex 的实测。GPT-5 mini 上 inform-only 的正确率64.0%，已接近 full64.2%；govern-only 的总成本反而最低。因而“govern负责正确率、inform负责效率”是有条件的实验概括，不是普遍因果分工。每题每配置只运行一次，不能推断跨重复运行稳定性。
- Ledger 对重复测试仅提示，不机械阻止；读取复用依赖结果成功、无截断、仍可见且未失效。它没有把“命令曾经执行过”当成“永远无需再执行”。无额外 LLM calls 不等于总维护成本为零。
- 两项 AGENTS.md 研究继续作为相异证据保留：[Lulla v2](https://arxiv.org/abs/2601.20404v2)、[Gloaguen v2](https://arxiv.org/abs/2602.11988v2)。当前候选设计不借任一论文推导普遍增删规则收益。

### 3. C1能解决多少：区分设计覆盖与实测效果

- E1/E2优先由交接粒度及指令投影解释，属于C1机制类别；E3有证据有效性问题，但首先适用既有Gate绑定；E4首先是统计口径问题，归文件轨。
- **设计覆盖：四片段都有既有或C1类的最小处理点。实际修复率：未知。** 不能写“C1解决4/4”或“已解决75%”。E3/E4并不独立，取样也无总体分母。
- 更关键的是，上述处理已经进入v0.14。因此当前最小动作主要是KEEP并核对C0实际加载和行为；这些历史片段不能单独证明需要一个新C1补丁，更不能证明需要C2。
- C0运行基线的已部署身份尚未核实。若实际未用v0.14，属于部署事实问题；修复部署不应计为C1 prompt收益。当前不从“未核实”推断“确实部署错误”。

### 4. C2的条件与实现选择

不要求先运行完C1才准研究C2；条件是：**有针对状态失真的正面证据，且现有最小处理不足以解释或处理该残余**。这可以来自已有trace，无须预先开发程序。

识别execution-state重建失败至少要看同一事件链：已有有效事实/结果 → 中间发生的修改或上下文变化 → 后续错误状态判断 → 由此产生重复动作或错误Gate。还应排除新SHA、外部变化、失效结果、必要复测等正当理由。当前E3只有其中部分证据。

| 条件 | 优先选择 | 仍需注意 |
| --- | --- | --- |
| 事实已可见且仍有效，Agent偶尔没有在结果后重新判断 | C2-Prompt可作为轻量候选：替换已有重复提示，突出该事件后的判断 | 文字提醒仍依赖模型执行；不能宣称持久化、自动去重或无成本 |
| 事实存在于现有artifact，但跨回合不可见或经常重建错 | 先复用现有Issue、review SHA、CI结果、checkpoint/host task pointer | 仅指针搬迁归C1；新增结果事件驱动的更新/失效/读取行为才归C2-State；pointer本身不保证新鲜或可访问 |
| 已有宿主暴露可验证的任务事件与状态 | 评估其是否覆盖实际失败边界及授权 | 本轮未核实Browser具体host能力，不列假定可用的API或自动运行功能 |
| 需要拦截命令、自动复用结果 | 作为更后的runtime候选，当前不ADD | 必须能判定命令等价、输入/环境变化、异步/外部变化、结果可见性及必要重试；不确定时不阻止真实核验 |

C2-State不是必然比C2-Prompt优先。**先复用事实，再按失败发生层选择机制**：可见事实的注意力遗漏可先考察Prompt；数据失真或不可见不能靠Prompt创造事实。二者不自动拆成两个正式实验，不新增Task Manager。

候选边界以行为差量定义：C1改变信息位置/冗余/既有Gate表达，不新建状态生命周期；C2改变结果到来后的状态更新/失效与下一动作联系。如果只是把现有Next/Gate提示改名为Frontier，不能计作独立C2干预。

### 6. 文件轨与后续证据边界

- **文件结构**：physical lines仅是proxy；告警指向自然职责评估，不能由行数直接推断上下文占用或强迫碎片化。
- **单次读取/输出**：观察成功与否、返回范围、截断、目标信息是否在返回中；缺失时读取必要范围。不要把“曾调用read”当成“完整看过内容”。
- **Session**：仅使用宿主真实暴露的占用、压缩或行为事件；无数据标unknown。单次大输出与会话累积压力分别归因，Browser/IDE独立判断。
- 后续取证只寻找能改变候选选择的缺口：有效部署身份；E3旧结果到后续错误判断的原始片段；若文件症状复发则读取/截断片段。优先读取现有记录，不要求用户重演长任务、不重跑S1/S2。
- 本轮完成四片段分类与设计覆盖分析，尚无C0/C1/C2实测对照。没有确定必须新增C2的残余案例；E3是最值得保留的状态有效性研究入口。
